# Мини-ERP для производства

Учётная система для небольшого производства 3D-печатных и лазерных изделий: игрушки,
светильники, ёлочные украшения. Всё в одной админке, на русском, в тенге.

Что она делает:

- **Справочники.** Материалы с цветами из общей палитры, формой учёта (штучный, листовой,
  рулонный, погонный, по весу) и предложениями поставщиков; оборудование со стоимостью часа;
  типы операций; категории изделий с кодами для артикулов.
- **Каталог** в четыре уровня: деталь (печатается или режется) → модель (из деталей и покупных
  частей, с цветовыми слотами) → вариант (расцветка) → товар (поштучно или набор, с артикулом,
  фото, габаритами).
- **Себестоимость** считается сама после любого изменения: материал по норме слайсера, работа
  станка, брак, обработка, сборка, упаковка, накладные; дерево показывает, из чего сложилась
  цена; снимок себестоимости фиксирует её на момент установки цены.
- **Склад.** Несколько складов (в том числе витрина образцов), остатки по материалам, деталям,
  изделиям и товарам, документы: закупки, выпуск деталей с браком, сборка, упаковка,
  перемещения, инвентаризация, оприходование и списание. Остаток в минус запрещён.
- **Роли.** Администратор, технолог, продавец (не видит себестоимость), наблюдатель.
  Ничего не удаляется насовсем: архив и история изменений.

Подробности и методика расчёта: [TZ.md](TZ.md). Этапы 1 (производство и себестоимость)
и 2 (склад) готовы; впереди этап 3 (деплой, QR и этикетки, импорт из слайсера)
и этап 4 (продажи: Kaspi, розница).

## Стек

Python 3.13, Django 5.2, PostgreSQL 16 (в Docker), админка на django-unfold, история
изменений django-simple-history. Зависимости описаны в `pyproject.toml` и закреплены
в `uv.lock` (менеджер [uv](https://docs.astral.sh/uv/)); `requirements.txt`
и `requirements-dev.txt` — экспорт из lock-файла для установки через pip там, где uv нет.

## Запуск для разработки (Windows)

Нужны uv, Git и Docker Desktop; Python 3.13 uv скачает сам. В Docker живёт только база
данных, Django запускается локально и подхватывает правки кода без перезапуска.

```powershell
# 0. uv, если ещё не стоит
winget install astral-sh.uv

# 1. База данных (контейнер erp-db-1, данные в томе pgdata)
docker compose up -d

# 2. Окружение: Python 3.13 и все зависимости (включая dev) в .venv, строго по uv.lock
uv sync

# 3. Настройки: скопировать и задать SECRET_KEY
copy .env.example .env
uv run python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"

# 4. Таблицы, начальные справочники (категории, цвета, операции) и роли
uv run manage.py migrate
uv run manage.py createsuperuser

# 5. (необязательно) примеры из ТЗ: светильник «Луна», ёлочные шары, закупки и остатки
uv run manage.py load_demo

# 6. Запуск
uv run manage.py runserver
```

`uv run` запускает команду в окружении проекта без активации; то же самое —
`.venv\Scripts\python manage.py …`. Новая зависимость: `uv add <пакет>` (в dev —
`uv add --group dev <пакет>`), после этого обновить экспорт:
`uv export --no-hashes --no-dev -o requirements.txt` и
`uv export --no-hashes -o requirements-dev.txt`.

Админка: http://127.0.0.1:8000/admin/. В `DEBUG=True` Django сам отдаёт загруженные фото
из папки `media/`.

Демо-данные загружаются один раз: команда откажется, если модели из примера уже есть.
Себестоимость пересчитывается автоматически; вручную — `uv run manage.py recalc_costs`.

## Настройки (`.env`)

Файл `.env` не попадает в git. Образец — `.env.example`.

| Переменная | Для чего | Разработка | Прод |
|---|---|---|---|
| `SECRET_KEY` | ключ подписи сессий и форм | любой | случайная строка от 40 символов, иначе приложение не стартует |
| `DEBUG` | подробные ошибки, отдача медиа Django | `True` | `False` |
| `ALLOWED_HOSTS` | домены, с которых принимаются запросы | `localhost,127.0.0.1` | `erp.example.kz` |
| `CSRF_TRUSTED_ORIGINS` | адреса с протоколом для форм за HTTPS | пусто | `https://erp.example.kz` |
| `DATABASE_URL` | подключение к PostgreSQL | `postgres://erp:erp@localhost:5432/erp` | то же, но с надёжным паролем |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT` | параметры контейнера базы | как в образце | пароль поменять, порт можно закрыть |
| `SECURE_SSL_REDIRECT` | перенаправлять http → https | не используется | `True` (по умолчанию) |

При `DEBUG=False` включаются защищённые cookie и перенаправление на HTTPS, а заголовок
`X-Forwarded-Proto` от обратного прокси считается признаком HTTPS.

## Запуск на проде (минимальный рабочий вариант)

Полноценный деплой со скриптами, службой и резервными копиями по расписанию — этап 3 ТЗ.
Ниже — то, что уже работает с текущими настройками. Подходит и для Linux, и для Windows.

**1. База данных.** Тот же `docker compose up -d` (контейнер перезапускается сам,
`restart: unless-stopped`) или отдельный PostgreSQL 16. В `.env` задать свой пароль
в `POSTGRES_PASSWORD` и `DATABASE_URL`.

**2. Код и окружение.**

```bash
git clone https://github.com/JxSol/MiniERP.git erp && cd erp
uv sync --no-dev --frozen            # ровно версии из uv.lock, без pytest и ruff
# без uv: python3.13 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

**3. `.env` для прода:** `DEBUG=False`, свой `SECRET_KEY`, `ALLOWED_HOSTS` и
`CSRF_TRUSTED_ORIGINS` с реальным доменом, `DATABASE_URL` с надёжным паролем.

**4. Таблицы, администратор, статика.**

```bash
uv run manage.py migrate
uv run manage.py createsuperuser
uv run manage.py collectstatic --noinput   # складывает статику в staticfiles/
```

**5. Приложение.** WSGI-сервер слушает только локальный адрес, наружу смотрит прокси.

```bash
uv run waitress-serve --listen=127.0.0.1:8000 config.wsgi:application
# то же самое напрямую из окружения: .venv/bin/waitress-serve …
# на Linux можно gunicorn: uv add gunicorn && uv run gunicorn config.wsgi -b 127.0.0.1:8000 -w 3
```

Чтобы это была служба, на Linux — unit для systemd:

```ini
[Unit]
Description=Mini-ERP
After=network.target docker.service

[Service]
User=erp
WorkingDirectory=/srv/erp
ExecStart=/srv/erp/.venv/bin/waitress-serve --listen=127.0.0.1:8000 config.wsgi:application
Restart=always

[Install]
WantedBy=multi-user.target
```

На Windows ту же команду регистрируют как службу через NSSM или запускают задачей
планировщика при старте системы.

**6. HTTPS, статика и фото.** При `DEBUG=False` Django не отдаёт ни статику, ни папку
`media/`, это делает обратный прокси. Самый простой — Caddy: сертификат получает сам.

```caddyfile
erp.example.kz {
    encode gzip
    handle_path /static/* {
        root * /srv/erp/staticfiles
        file_server
    }
    handle_path /media/* {
        root * /srv/erp/media
        file_server
    }
    reverse_proxy 127.0.0.1:8000
}
```

Для nginx нужны такие же два `location` на `staticfiles/` и `media/` и `proxy_pass`
с заголовком `X-Forwarded-Proto $scheme`.

**7. Резервные копии.** Две вещи: база и папка `media/` с фото.

```bash
docker compose exec -T db pg_dump -U erp -Fc erp -f /tmp/erp.dump && docker compose cp db:/tmp/erp.dump ./backup/erp-$(date +%F).dump
# восстановление: docker compose cp backup/erp-2026-10-22.dump db:/tmp/erp.dump && docker compose exec -T db pg_restore -U erp -d erp --clean /tmp/erp.dump
```

Папку `media/` копируйте как обычные файлы. Делать это раз в сутки и хранить копии не на
том же диске.

**8. Обновление.**

```bash
git pull
uv sync --no-dev --frozen
uv run manage.py migrate
uv run manage.py collectstatic --noinput
# перезапустить службу приложения
```

## Роли

Группы создаются автоматически при `migrate` (см. [core/roles.py](core/roles.py)).
Пользователя добавляют в группу на странице «Система → Пользователи».

| Роль | За что отвечает |
|---|---|
| Администратор | Владелец системы: справочники, общие настройки, пользователи и роли; может всё, включая отмену проведённых документов. Видит себестоимость |
| Технолог | Производство и склад: материалы с предложениями поставщиков, детали, модели, варианты, товары, все документы склада. Видит и фиксирует себестоимость, записи не удаляет (архив) |
| Продавец | Товары для продажи (карточки, артикулы, фото), на этапе продаж — продажи и скидки в пределах лимита. Без себестоимости, прибыли, цен закупки, склада и производства |
| Наблюдатель | Только просмотр каталога без себестоимости: бухгалтер, партнёр, стажёр |

Те же описания видны в системе: «Система → Роли» и под полем «Роли» в карточке пользователя.

## Как устроен код

| Приложение | Что внутри |
|---|---|
| `core` | Общие настройки, метки, размеры, роли, базовые классы админки, формат чисел, справка «О разделе» и пояснения полей, демо-данные |
| `catalog` | Материалы (форма учёта, цвета, предложения поставщиков, история цен), оборудование, типы операций, категории материалов |
| `production` | Детали, модели, варианты, категории изделий с кодами для артикулов, генераторы (варианты, наборы, размеры) |
| `sales` | Товары (поштучные и наборы) с артикулами, упаковка, снимки себестоимости |
| `gallery` | Фото с правилами «главное / техническое / дополнительные» |
| `costing` | Движок себестоимости (`engine.py`, чистые функции), загрузчик данных и пересчёт |
| `stock` | Склады и витрина, остатки, движения, документы: закупки, выпуск деталей, сборка, упаковка, перемещения, инвентаризация, оприходование, списание; причины прихода и списания |

Коды генерируются и не редактируются: деталь `C-FDM-0000001`, модель `M-0000001`,
вариант `M-0000001_01`, товар `SKU-0000001` (служебный). Артикул товара для людей
и площадок (`LT0001A`, набор `LT0001A-N50`) собирается по правилам ТЗ 6.8а.

## Проверки

Нужен запущенный Postgres (`docker compose up -d`): тесты создают базу `test_erp`.

```powershell
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

То же самое делает GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml)):
ставит зависимости строго по `uv.lock`, гоняет линтер и тесты и проверяет, что миграции
актуальны. Пример «Луны» из ТЗ (п. 4.9) — обязательный тест:
итог должен совпадать до копейки; отдельный тест следит, чтобы ни на одной странице
админки не было сырых чисел вроде «600,0000».

## Перевод интерфейса

Подписи unfold, которых нет в его пакете, переведены в `locale/ru/LC_MESSAGES/django.po`.
После правок: `uv run python scripts/compile_locale.py` (собранный `django.mo` коммитится вместе с `.po`).
